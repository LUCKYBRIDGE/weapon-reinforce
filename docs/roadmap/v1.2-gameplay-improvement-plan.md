# Weapon Reinforce 1.2 게임성 개선 계획

작성 기준: 2026-09-09  
기준 런타임: 1.1.0 + P1 구조 개선 완료 상태  
목표: 구조를 다시 뜯지 않고 **반복감, 선택의 의미, 무기 개성, 후반 난이도, 교육적 연결감**을 개선한다.

## 1. 1.2의 기본 원칙

1. 1.1의 저장 형식과 serverless 구조를 유지한다.
2. 강화 → 퀴즈 → 탐사 → 귀환/전리품 → 준비물의 핵심 루프를 유지한다.
3. 자동 전투를 액션 게임으로 바꾸지 않는다.
4. 단순히 콘텐츠 수만 늘리지 않고, 같은 플레이를 반복할 때 다른 판단과 결과가 생기게 한다.
5. 역사적 사실과 전투 판타지의 경계는 현재보다 약화하지 않는다.
6. 모든 밸런스 변경은 `validate:balance`의 수치 비교를 거친다.
7. 새로운 런타임 분석/광고/계정/서버를 추가하지 않는다.

## 2. 1.1 기준선 진단

### 2.1 현재 콘텐츠 밀도

| 항목 | 현재 |
| --- | ---: |
| 강화 무기 | 7종 |
| 퀴즈팩 | 9팩 |
| 퀴즈 문항 | 762문항 |
| 탐사 지역 | 3개 |
| 역사층 | 7개 |
| 적 | 6종 |
| NPC | 3종 |
| 사건 | 3종 |
| 가상 전리품 | 6종 |
| 준비물 | 3종 |

탐사 콘텐츠는 기능적으로 완성되어 있으나, NPC와 사건은 지역마다 사실상 1종씩이고 청동 안개 지역의 5~6층 일반 적도 1종뿐이다. 최근 ID 반복 회피와 적 2연속 뒤 지원 조우 보장이 있어도 **후반 반복 플레이에서는 같은 이름·효과·이미지를 다시 볼 가능성이 높다.**

### 2.2 조우 구조

- 1층: 적 강제
- 2~6층: 기본 유형 추첨 적 60 / NPC 23 / 사건 17
- 적 2연속 뒤: NPC 또는 사건 강제
- 최근 2개 조우 ID 반복 회피
- 7층: 최종 적 강제

현재 구조는 억울한 적 연속을 방지하는 안전장치는 좋다. 다만 NPC/사건이 자동 해결되고, 다음 층에서 플레이어가 하는 핵심 선택은 대부분 **귀환 또는 계속 탐사**이므로 중간 과정의 플레이어 agency가 제한된다.

### 2.3 무기 개성

현재 7종은 공격명, 자세, 치명타 확률/배율, 방어, 적중 회복이 다르다.

- K2: 낮은 치명타, 방어/회복 없음
- 월도: 약한 방어 + 낮은 치명타
- 장도·쌍수도: 높은 치명타 배율
- 환도: 높은 치명타 + 방어
- 칠지도: 높은 방어
- 한국식 동검: 높은 치명타 + 소량 회복
- 비파형동검: 가장 높은 치명타 + 방어 + 회복

수치 차이는 실제 계산에 반영되지만 전투가 자동 진행되므로, 플레이어 입장에서는 **무기 교체가 '숫자가 더 강해짐'으로 느껴질 가능성**이 있다. 1.2에서는 자동 전투를 유지하면서 각 무기의 특징이 전투 로그와 연출에서 더 분명하게 드러나게 한다.

### 2.4 탐사 밸런스 실측

`scripts/simulate-game-balance.mjs`의 단계별 5,000회 시뮬레이션 기준:

| 무기 단계 | 7층 생존 | 평균 깊이 |
| ---: | ---: | ---: |
| +1 | 0.0% | 4.64 |
| +2 | 0.0% | 5.19 |
| +3 | 0.0% | 5.81 |
| +4 | 0.0% | 6.14 |
| +5 | 0.0% | 6.63 |
| +6 | 0.9% | 6.95 |
| +7 | 12.0% | 7.00 |

추가한 +7 준비물 비교 5,000회 기준:

| 준비물 | 7층 생존 | 사망 |
| --- | ---: | ---: |
| 없음 | 11.6% | 88.4% |
| 여행 붕대 | 20.1% | 79.9% |
| 공명 손질 천 | 18.3% | 81.7% |
| 균열 안전 주머니 | 10.9% | 89.1% |

해석:

- +7의 평균 깊이는 7.00이므로 **최종층 도달 자체는 안정적**이다.
- 문제는 최종층 생존률이다. 최고 무기로도 기본 약 1/9, 전투형 준비물을 써도 약 1/5 수준이다.
- 안전 주머니는 전투 생존용이 아니라 패배 손실 완화용이므로 생존률이 오르지 않는 것이 정상이다.
- 따라서 1.2에서 전체 적을 일괄 약화하면 +1~+6의 단계 차이를 무너뜨릴 수 있다.
- 우선 조정 대상은 **최종층 전투와 +7 준비물 효용**이다.

### 2.5 강화·퀴즈 진행 속도

현재 보수적 시뮬레이션은 대성공과 복원 무기고를 사용하지 않는다.

- 기본 타이밍: +1 → +7 평균 191.5회 강화 시도, 19,736냥, 약 235문제
- 항상 PERFECT: 평균 93.3회 강화 시도, 11,093냥, 약 132문제

이 값은 실제 플레이보다 보수적인 상한에 가깝다. 1.2에서 곧바로 퀴즈 보상을 크게 올리거나 강화 확률을 낮추지 않는다. 먼저 **대성공·복원까지 포함한 현실적인 진행 시뮬레이션**을 추가한 뒤 조정한다.

## 3. 1.2에서 해결할 문제

### A. 탐사 반복감

문제:
- NPC/사건이 지역당 1종
- 5~6층 일반 적이 1종
- 지원 조우가 자동 해결되어 반복 플레이 시 판단이 적음

목표:
- 같은 지역을 반복해도 조우 내용과 결과가 쉽게 동일해지지 않게 한다.

### B. 최고 단계 최종층 난이도

문제:
- +7이 7층에 도달해도 무준비 생존 11.6%
- 전투 준비물 사용 시에도 18~20% 수준

목표:
- +7을 얻은 보상이 느껴지되 최종층이 자동 승리가 되지는 않게 한다.

### C. 무기별 체감 차이

문제:
- 수치 차이는 있으나 자동 전투에서 차이를 읽기 어렵다.

목표:
- 공격 로그·효과·전투 연출만 보아도 현재 무기의 강점을 설명할 수 있게 한다.

### D. 강화 진행 시간의 불확실성

문제:
- 현재 시뮬레이션은 실제 대성공/복원 사용을 반영하지 않아 튜닝 근거가 불완전하다.

목표:
- 실제 규칙 기반 평균 문제 수와 강화 시도 수를 먼저 계측한 뒤 경제를 조정한다.

## 4. 1.2 확정 범위

### Phase 1 — 반복감 개선

우선순위: 최상

1. 지역별 지원 조우 후보를 최소 2종으로 만든다.
   - NPC: 3 → 최소 6종
   - 사건: 3 → 최소 6종
2. 청동 안개 5~6층 일반 적을 최소 2종 후보로 만든다.
   - 전체 적: 6 → 최소 7종
3. 최근 조우 회피 규칙은 유지한다.
4. 60/23/17 기본 유형 비율은 1차에서는 유지하고, 콘텐츠 추가 후 시뮬레이션으로 실제 빈도를 다시 본다.
5. 새 조우는 기존 회복/공격/방어/lootBonus를 단순 복제하지 않고 서로 다른 조합을 사용한다.

완료 기준:
- 모든 지역에 NPC 2종 이상, 사건 2종 이상
- 5~6층 일반 적 2종 이상
- 100회 이상 시드 기반 조우 검증에서 알 수 없는 조우/무한 반복 없음
- 기존 적 2연속 지원 보장 유지

### Phase 2 — 지원 조우에 작은 선택 추가

우선순위: 높음

NPC/사건 전체를 복잡한 분기형 RPG로 만들지는 않는다. 일부 지원 조우에 **2택 1 선택**을 추가한다.

예:
- 즉시 회복 vs 다음 전투 공격 보너스
- 안전한 전리품 1회 vs 체력 소모를 감수한 추가 조사
- 기록 조각 우선 vs 전리품 우선

설계 원칙:
- 한 조우에서 선택은 최대 2개
- 선택 결과는 짧고 예측 가능하게 표시
- 잘못된 선택으로 즉사하거나 강화 단계가 손실되지 않음
- 저장 중간 상태를 지원해야 하므로 run schema와 validator를 함께 갱신
- 선택하지 않은 채 새로고침해도 동일 조우·동일 선택지가 복구되어야 함

완료 기준:
- 최소 NPC 2종 + 사건 2종에 의미 있는 2택 선택
- 선택 결과가 저장/복구됨
- 모바일 390px에서 두 선택지가 가로 넘침 없이 표시됨

### Phase 3 — +7 최종층 난이도와 준비물 조정

우선순위: 높음

초기 목표 범위:

- +6 무준비 7층 생존: 5% 이하 유지
- +7 무준비 7층 생존: **20~30%**
- +7 여행 붕대/공명 손질 천: **30~45%**
- 안전 주머니는 전투 생존 증가를 목표로 하지 않음

조정 순서:

1. 최종 적의 HP/방어/강공 주기 중 하나만 먼저 조정
2. +7 무기 자체의 전체 공격력을 일괄 올리지 않음
3. 붕대/손질 천의 비용 대비 효과를 재측정
4. 목표 범위에 들어온 뒤 다른 층 생존률이 무너지지 않았는지 확인

이 방식은 +1~+6의 단계별 위험도를 보존하면서 최종층만 조절한다.

### Phase 4 — 무기 개성 가시화

우선순위: 중간

1. 자동 전투 방식은 유지한다.
2. 각 무기의 기존 combatProfile을 중심으로 전투 로그와 연출 차이를 강화한다.
3. 신규 패시브가 필요하면 한 무기당 최대 1개로 제한한다.
4. 새 패시브는 저장 파일에 별도 영구 상태를 만들지 않는 순수 계산형을 우선한다.

방향 예시:
- 높은 치명타 무기: 치명타 시 전용 문구/타격 연출
- 방어형 무기: 피해 감소량을 명시
- 회복형 동검: 회복 발생을 더 명확하게 표시
- K2/월도/쌍수도처럼 현재 수치만으로 특징이 약한 무기는 기존 설정과 어긋나지 않는 계산형 특징을 검토

완료 기준:
- 7개 무기 모두 전투 로그에서 고유 공격명과 강점을 읽을 수 있음
- 동일 단계 숫자 증가만으로 보이지 않음
- 기존 역사 설명과 게임 전투 효과를 혼동시키는 문구 없음

### Phase 5 — 실제 강화 진행 속도 계측 후 조정

우선순위: 중간

`simulate-game-balance.mjs`에 다음을 추가한다.

- 대성공 +2/+3
- 가짜 대성공은 경제 변화 없음으로 처리
- 복원 무기고 사용 정책 시나리오
- 쉬운/중간/어려운 퀴즈팩 보상 범위별 문제 수
- GOOD/PERFECT 혼합 타이밍 시나리오

그 결과를 본 뒤 다음 중 최소 변경만 선택한다.

- 강화 비용
- 단계별 성공률
- 타이밍 보너스
- 퀴즈팩 보상
- 복원 가격

1.2에서는 여러 경제 레버를 동시에 바꾸지 않는다.

## 5. 1.2 비범위

다음은 1.2에서 하지 않는다.

- 멀티플레이
- 서버 저장/로그인
- 온라인 랭킹
- 실시간 PvP
- 액션 전투 조작
- 강화 트리 분기
- 7단계 무기 역사 순서 교체
- 퀴즈 원본 프로젝트에 대한 런타임 의존
- 기존 JSON 저장 파일을 의도적으로 깨는 대규모 저장 재설계
- 역사 실재 인물을 적으로 직접 사용하는 방향

## 6. 검증 전략

모든 Phase는 다음을 유지한다.

```bash
npm run validate:all
```

추가 검증:

### 조우 변경
- `validate:expedition`
- 지역별 후보 수
- ID 중복
- depth 범위
- 지원 조우 선택 상태 sanitize
- 최근 조우/적 연속 보정

### 경제·준비물
- `validate:economy`
- 구매/소비 transaction 중복 방지
- 준비물 효과별 +7 생존 비교
- 전리품 획득/손실 정산

### 밸런스
- 기존 단계별 5,000회
- +7 준비물별 5,000회
- 목표 생존 구간 assertion은 실제 튜닝 Phase에서만 추가

### UI
- 데스크톱
- 768px급 태블릿
- 390px급 모바일
- 키보드/터치
- 지원 조우 선택 중 새로고침

## 7. 구현 순서

1. **1.2-01 조우 다양성 데이터 확장**
2. **1.2-02 조우 선택 상태/화면**
3. **1.2-03 최종층 밸런스 조정**
4. **1.2-04 무기 개성 가시화**
5. **1.2-05 실제 강화 경제 시뮬레이션 및 필요 시 소폭 튜닝**
6. **1.2-06 모바일/저장/회귀 최종 검증 및 1.2 릴리스**

각 단계는 별도 브랜치/PR로 진행하며 앞 단계가 검증된 뒤 다음 단계로 넘어간다.

## 8. Definition of Done

1. P1의 훅 경계를 되돌리지 않는다.
2. 탐사 반복 플레이에서 지역별 NPC/사건이 한 종류로 고정되지 않는다.
3. 최소 일부 지원 조우에서 플레이어 선택이 결과에 영향을 준다.
4. +7 최종층 생존률이 목표 범위에 들어간다.
5. +6 이하가 최종층을 쉽게 완주하지 않는다.
6. 무기 7종의 전투 개성이 로그/연출에서 구분된다.
7. 강화 경제 변경은 실제 규칙 시뮬레이션 결과에 근거한다.
8. 저장/복구 및 JSON 백업 호환성이 유지된다.
9. `npm run validate:all`이 오류와 ESLint 경고 없이 통과한다.
10. 데스크톱·태블릿·모바일 핵심 흐름을 재검증한다.
